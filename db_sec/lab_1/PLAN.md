# Лабораторная работа №1 — Организация данных и разграничение доступа

Статус: выбран вариант 1 (рецепты и аптеки).

## Вариант 1
Отношение 1 — рецепты: номер рецепта (PK), код заболевания,
ФИО пациента (AK1), дата выписки (AK1), ФИО врача,
срок действия в днях (если есть), наименование лекарства,
код лекарства, признак использования рецепта, номер аптеки (FK).
Отношение 2 — аптеки: номер аптеки (PK), ФИО провизора (AK1),
город аптеки (AK2), адрес аптеки (AK2).

Права доступа:
- врач: видит все данные рецептов, кроме ФИО пациента и кода
  заболевания; эти два поля видит только для рецептов, которые
  выписал сам; может добавлять рецепты и изменять срок действия
  в своих рецептах.
- провизор: видит все данные рецептов, кроме ФИО врача и кода
  заболевания; может изменять признак использования и номер
  аптеки только для ещё действующих на момент изменения рецептов.

## Порядок выполнения (по методичке)
1. Создание схемы данных на SQL (PostgreSQL): все отношения, ключи (PK, FK, UNIQUE), свойства атрибутов (типы, NOT NULL, CHECK, DEFAULT).
2. Разработка матрицы доступа, детализированной до атрибутов, на основе прав из варианта:
   - операции CRUD (Create, Read, Update, Delete);
   - ограничения на работу с атрибутами;
   - горизонтальные ограничения (доступ не ко всем кортежам).
3. Реализация разграничения встроенными средствами СУБД: GRANT / REVOKE / DENY, роли, RLS-политики (CREATE POLICY ... FOR SELECT/UPDATE ... USING).
4. Чего нельзя выразить стандартными средствами — дать более широкие права и отразить в отчёте (функции/представления/триггеры на этом этапе НЕ создаём).

## Структура файлов (черновик)
- `schema.sql` — DDL: таблицы, ключи, ограничения (с DROP ... IF EXISTS ... CASCADE).
- `data.sql` — заполнение: INSERT + при необходимости plpgsql-функция-генератор.
- `access.sql` — роли, GRANT/DENY/REVOKE, RLS-политики.
- `matrix.md` — исходная матрица доступа и итоговая после применения GRANT/POLICY.
- `report.md` — отчёт по 11 пунктам из методички.
